# Cherre 深研（房地产数据平台）— 2026-10-02

> 只读调研：browser.search + browser.open，无 live browser、无注册/登录。
> 调研视角：DealDesk 是给单个投资人（Miao）的 N=1 核保台——deal intake（地址/PDF→结构化，多源 fallback：TopHap→RentCast→网页→Census）→ underwriting（三栏）→ PDF 投资备忘录。找的是 Cherre 身上**具体可学的功能点**。

## 定位一句话

Cherre 是房地产行业的**数据连接/标准化平台**（不是数据卖家）：把企业内部系统（ERP、leasing、deal management）、公开数据（tax/recorder/deed）和第三方数据商的数据，接入、映射到一套标准数据模型，用 **single GraphQL API** 对外提供，号称"real estate single source of truth"。

**定位纠正（重要）**：Cherre **现属 RealPage**——2026-07-14 官宣收购（条款未披露），RealPage CEO Dirk Wakeham 明确"保持独立运营单位、保留品牌"。Cherre **不是 CoreLogic 的子公司**：CoreLogic（2025 年改名为 Cotality）是 Cherre 的**数据供应商之一**（canvasbusinessmodel 列为 data provider：CoreLogic / Yardi / ATTOM）。定价模式：SaaS base platform fee + 按接入数据集数量/复杂度收费 + 附加数据可从 Connections Catalog 单独购买。目标客户=最大型全球资本配置者（RealPage CEO 原话："Cherre's ideal customers today are the largest global capital allocators. Think of Brookfield, Nuveen or Starwood."），外加保险公司、lender、asset manager、proptech 公司。SourceForge 显示 pricing="No information available"——企业级报价、私下谈。

## 核心功能（速览）

1. **三路 ingest**：Cherre Connectors（预置连接器：ERP、deal management、leasing 平台）、Submission Portal（第三方 vendor/投资经理提交数据：映射+设规则自动化 ingestion/standardization/validation）、Ingress（secure SFTP 给 managed service provider 提交）。
2. **Data Fabric / Real Estate Knowledge Graph**：3.3B+ addresses 已解析的公开数据（property characteristics、recorder/deeds、valuations、tax/assessments、liens/mortgages、boundaries、demographics、POI），ML 做 entity resolution。收购官宣称已 resolve 4B+ entities / $4T real assets。
3. **Schema mapping engine**：任意源⇄目标、以及源→Cherre 标准数据模型的灵活可配映射。
4. **Single GraphQL API**（Hasura 构建）：跨所有连接数据集单次查询、PostGIS 地理查询、BigQuery 层上的大批量 pull、sum/distinct/average 聚合。
5. **数据质量 UI**：data observability（table/column profiling、status monitoring）、data validation（可自建/管理的校验规则库＋告警）。
6. **Egress**：一键导出到 Snowflake/AWS/Azure/BigQuery/SFTP，模式=一次性 initial load + 后续 incremental updates。
7. **Connections Catalog / Lightning Connections**：预接入的数据商目录（一小时内加到仓库），如 Advan、BuildCentral、BuildZoom、ClimateCheck、Regrid、Rental Beast（800 万 rental listings）、RentCast（Cherre 的 data partner！）、DealStat（PDF 非结构化抽取）、HazardHub（property risk）。
8. **安全合规**：SOC-2、RBAC、静/动加密。

## 可学的 3-5 条（每条：功能名 / 它具体怎么做 / 对 DealDesk 的启发 / 证据）

### 1. 标准数据模型 + 可配 schema mapping engine（最值得学）

- **它具体怎么做**：Cherre 不为每个数据源写硬编码解析，而是维护一套 **Cherre 标准数据模型**；每个新数据源通过"schema mapping engine"把源字段映射到标准模型——"flexible and configurable, allowing you to map between source and target systems, as well as mapping to Cher's standard data model"。新数据商（Lightning Connections）进来时只需写映射，消费侧（API/报表）永远只对标准模型。
- **对 DealDesk 的启发**：我们现在的 intake 是 TopHap→RentCast→网页→Census 四源 fallback，但每个源字段形状不同，解析逻辑散在 intake 代码里。学 Cherre 的做法：先定一个 **canonical deal record schema**（地址/单元数/租金/NOI/税/估价字段 + provenance），每个数据源写成独立的 `connector` 模块（map 函数：源→canonical），underwriting 只消费 canonical。加新源 = 新增 connector 文件 + 映射表，不动核保逻辑。这是 D470"拼装式创新"原则在数据层最直接的落地。
- **证据**：https://cherre.com/products/platform/ — "Cherre's schema mapping engine is flexible and configurable, allowing you to map between source and target systems, as well as mapping to Cher's standard data model."

### 2. Entity resolution（同一资产的多源身份归一）

- **它具体怎么做**：Cherre 解决房地产数据"无唯一 ID"的根本问题——"real estate data is very complex and there is no unique ID to easily connect disparate datasets"（CEO 访谈）。用 ML/图算法做 entity resolution：语义邻域（semantic neighborhood）结构相似度 + 名称语言相似度，把"leasing 系统里的一个地址、运营平台里的另一个单元号、税单里的另一个 parcel ID"识别为同一资产。收购官宣原话："A single property can appear as one address in a leasing system, a different unit number in an operations platform, and a separate parcel ID in a tax record... until something resolves those identities... no AI can reason across it."
- **对 DealDesk 的启发**：我们的痛点正是这个——同一 deal，TopHap 给的单元数、PDF 里 OM 的单元数、Census 的地址格式经常对不上。我们可以做**轻量版 identity resolution**：intake 时先做地址归一化→geocode→APN/parcel ID 交叉验证，把多源记录合并成一条 canonical deal，每条字段标注来源+置信度，对不上的字段 flag 出来而不是静默取第一个。这比现在"fallback 取到即用"可靠一个档次。
- **证据**：
  - https://www.businesswire.com/news/home/20260714560587/en/RealPage-Acquires-Cherre-Creating-a-Trusted-AI-Powered-Intelligence-Platform-Across-the-Full-Real-Estate-Capital-Stack（收购官宣，identity 问题原文）
  - https://blog.cherre.com/2021/07/02/improving-knowledge-graph-quality-with-neighborhood-based-entity-resolution/（技术博客：semantic neighborhood + linguistic similarity 方法）
  - https://www.inman.com/2026/07/21/realpage-cherre-ai-data-acquisition-interview/（CEO："Cherre is not really a data company. It is a platform that allows customers to aggregate data."）

### 3. Submission Portal 式"规则驱动的数据校验层"

- **它具体怎么做**：Cherre 的 Submission Portal 让用户"Map your data and set rules to automate data ingestion, standardization, and validation"——接入时就配置校验规则（标准测试库 + 自建规则 + 告警），数据质量问题在进入仓库前被拦截；配套 data observability（table/column profiling、status monitoring），每批数据"进、过、出"的状态、完整度、交付情况全可见。
- **对 DealDesk 的启发**：intake 目前缺"守门员"。建议加一个 **validation rules 层**（建议独立模块 `validators.py`，规则表可配）：例如"租金偏离 RentCast 中位数 ±30% → warn"、"TopHap 与 PDF 的单元数不一致 → fail 需人工确认"、"税单年份早于 2 年 → stale flag"。规则结果在 intake UI 里以 pass/warn/fail 展示，**只有 fail 清零才能进 underwriting**。这和现有 `uw-field-lineage.md`（字段血缘）是互补的：血缘告诉你数从哪来，校验告诉你数能不能信。
- **证据**：https://cherre.com/products/platform/（Submission Portal + API/observability 段落）；https://resourcelinkai.com/reviews/detailed-reviews/ai-real-estate-tools-detailed-reviews/cherre-detailed-review/（"Users can create, manage, and customize data validation checks, alerts, and rules... standard library of tests across various data connectors"）。

### 4. Connector 注册表 + 增量更新（Egress 模式倒置）

- **它具体怎么做**：Cherre 把每个数据源做成**注册在案的 connector**（有标准数据模型、状态、数据字典、license 表），新增数据源 = 目录里选一个（Lightning Connections 数小时可加）；Egress 侧模式是"one-time initial load followed by incremental updates"——首刷全量、之后只增量。
- **对 DealDesk 的启发**：两点。① 把现在的 fallback 链**形式化为 connector 注册表**（`connectors/` 目录：每个源一个文件，声明 coverage/cost/refresh cadence/license 限制 + map 函数），加源不再改 intake 主逻辑；② 学"增量更新"：deal 重访时只刷新会变的字段（rent comps、tax），不全量重拉——省 API 钱、快，且每次刷新留 diff 日志（"租金中位数 2,100→2,250，上涨 7%"），这对 Miao 追踪一个 deal 的变化很有用。
- **证据**：https://cherre.com/products/platform/（"select the licensed tables you want to export and Cherre Egress will provide a one-time initial load followed by incremental updates"）；https://blog.cherre.com/2021/09/17/cherre-introduces-lightning-connections-and-expands-connections-catalog/（Lightning Connections：目录数据集数小时接入仓库，"within days vs. the months required when done as one-offs"）。

### 5. "非黑盒"数据观：per-field provenance + 完备度评分进报告

- **它具体怎么做**：Cherre CEO 在 GlobeSt 访谈里说客户要的是基础设施和工具，"we're not looking for black box AI or magic"；平台把每批数据的状态、完整度、变换过程做成可观测的 UI，而不是只给结论。
- **对 DealDesk 的启发**：投资备忘录（PDF）加一个**数据完备度表头**：例如"15/18 字段已解析；租金←RentCast（高置信）、NOI←PDF 抽取（未验证）、税←TopHap（2024 年数据）"。Miao 做决策时一眼知道哪些数是实的、哪些是猜的。这比单纯把数字算得更精更有价值——核保台的信任来自"诚实标注不确定性"，和我们 D9/材质诚实铁律同源。
- **证据**：https://www.globest.com/2024/09/19/what-cre-really-wants-from-data/（CEO Salmanson："Get us off the ground and give us the infrastructure and tools that let us build more and more things, but we're not looking for black box AI or magic."）；https://resourcelinkai.com/reviews/detailed-reviews/ai-real-estate-tools-detailed-reviews/cherre-detailed-review/（data observability / validation 段落）。

## 不适合我们的（企业级设计，N=1 学了是负担）

1. **多租户数据仓库 + 组织级 single source of truth**：Cherre 解决的是"全公司几百人用同一份数据"的问题（BigQuery/GKE/Cloud SQL、Snowflake Egress、BI 集成）。DealDesk 只有一个用户（Miao），建仓库/Egress 纯属 overhead。
2. **Connections Catalog 式的数据商市场**：Cherre 的商业模式是 base fee + 按数据集收费 + 帮数据商卖数据（licensing）。我们是 $0 栈、按次付费 API（RentCast/TopHap），搞"目录+许可"没有意义，反而增加谈判成本。
3. **SOC-2 / RBAC / 企业合规全套**：Cherre 的 SOC-2、role-based security 是卖给 Brookfield/Nuveen/Starwood 的门票。N=1 台子做到这个程度是过度工程；我们的合规需求=不泄露 Miao 的 deal 数据，靠本机部署+访问控制即可。
4. **全组合实时绩效监控 / re-forecasting**：Cherre 的 asset & portfolio dashboards、real-time portfolio performance 是为管理几十亿资产的机构做的。DealDesk 是逐笔 deal 核保，不需要组合层实时看板（真需要时，deal 列表页加个汇总行就够了）。
5. **Inman 评测原话作证**："Quite frankly, Cherre might be too much for some brokerages. Perform thorough due diligence."（https://www.inman.com/2017/12/04/cherre-uses-big-data-to-manage-and-market-your-business/）——连中型 brokerage 都嫌重，N=1 个人台子更只能取其**设计思想**（标准模型、entity resolution、校验层），不能取其**架构规模**。

## 一句话总结

Cherre 最值得 DealDesk 偷的是它的**数据层设计哲学**——"先定标准模型，再让所有源映射进来；先解决'这是不是同一处资产'，再谈分析"——而不是它的企业级规模；N=1 版本 = canonical deal schema + 轻量 entity resolution + intake 校验规则层 + connector 注册表，四件套落地即可。
