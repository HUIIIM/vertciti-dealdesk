# Dealpath 竞品深研报告（2026-10-02）

研究员：J.A.R.V.I.S. 竞品 researcher ｜ 方法：公开页面抓取 + 评测站用户评论（未注册/未登录/未付费）

## 定位一句话

Dealpath = **机构级商业地产交易管理平台**（2014 年创立，旧金山，Blackstone/AEW/Starwood 等 300+ 机构客户，$10T 交易量经手）：核心是把 OM→pipeline→承销→IC 决策→组合管理全链路变成一套"单一事实源"数据库，AI（AI Studio，2025-10 发布）挂在结构化数据上做筛查/提取/可比/文档生成。

## 核心功能（官方口径）

- **AI Extract**：OM/flyer 自动抽取，2024 上线；官方称"90+ listing/property 字段、抽取<1 分钟、准确率 95%"（businesswire 2025-10-14）。已扩展到 debt OM（融资需求书）。
- **AI Deal Screening**：上传 OM、rent roll、T12、BOV、pro forma → 秒级生成 tear sheet，含 portfolio fit、back-of-the-envelope 分析、deal highlights、recommended next steps。
- **AI Comps**：三个来源推荐可比交易——自有 proprietary DB、MSCI's RCA、第三方数据商；deal 页一键 attach/pass。
- **AI Excel Assistant**：Claude/ChatGPT 的 Excel add-in 直接引用 firm 已验证的假设/可比/历史 deal 数据做承销。
- **Dealpath MCP**：pipeline/comps/underwriting/historical deals/portfolio 通过 MCP 进 Claude/Copilot，用自然语言问 pipeline 状态，答案锚定实时 Dealpath 数据（role-based permissioning）。
- **Dealpath Connect**：私募 listings 交换网络（JLL/CBRE/Cushman 的 listings 直灌 buy-side pipeline）；官方称 19,000 listings、$930B 总交易额，buy-side 接触率 ~60%。
- **Portfolio Insights / Reporting**：实时 dashboard、recurring 报告、IC memo 从 Dealpath 输入直接生成（用户评论证实）。
- 定价：不公开报价，企业定制（第三方清单估计 ~$12k/年起）；官网 plans 页：**最少 5 用户起售**，实施 6-8 周，white-glove CSM 陪跑。

## 可学 3-5 条（具体功能点）

### 1. 一键 Tear Sheet（秒级单页摘要）——AI Deal Screening 的产品化形态
- **Dealpath 具体怎么做**：上传 OM/rent roll/T12/BOV/pro forma 后，系统生成一张 tear sheet，固定结构 = **portfolio fit（与现有组合的匹配度）+ back-of-the-envelope 分析（信封背估算）+ deal highlights + recommended next steps**。筛查从"数小时"压缩到"数分钟"（AI 页面原文：*"Upload OMs, rent rolls, T12s, BOVs, pro formas, and more to create a tear sheet in seconds. See how a deal fits with your portfolio and get a back-of-the-envelope analysis, deal highlights, and next steps."*）。证据：https://www.dealpath.com/ai/
- **对 DealDesk 的启发**：DealDesk intake 完成后、承销三栏之前，加一个**自动生成的 deal 一页纸**——关键字段（价格、NOI、cap rate 全口径现金需求、月供、DSCR）+ 三条 highlights + 一条"下一步建议"（如"补 T12""约看房""pass 原因"）。这张纸可直接进 PDF 备忘录封面页，Miao 不用翻三栏就能做 go/no-go。成本低（纯模板渲染已有数据）。
- **优先级**：P0。纯加法，不碰现有链路。

### 2. 可比交易 Attach/Pass 工作流——AI Comps
- **Dealpath 具体怎么做**：每笔 deal 系统从三个来源自动推荐 comps（**自有 proprietary deal DB、MSCI's RCA、第三方数据商**），relevance 按 proximity/price/square footage 排；在 deal 页面上每个 comp **一键 attach（一键并入）或 pass（一键丢弃）**，attach 的 comps 进入承销依据。（AI 页面原文：*"AI Comps recommends comparable transactions from three sources... The most relevant comps surface automatically for each deal, and you can attach or pass with one click."*）证据：https://www.dealpath.com/ai/
- **对 DealDesk 的启发**：DealDesk 已有 TopHap（get_property_cma 等 10 tools）+ 独立估价 SOP。学的是**交互形态**：在估价步骤给一个 comps 候选列表，每个 comp 显示来源/距离/单价/可比维度，Miao 点"采用"即写入估值依据、点"丢弃"即记录排除理由（排除理由进审计日志，满足 deal intake 铁律"不采信卖方数字"的留痕要求）。比现在"调 TopHap 看结果"多一步人机协同，但决策可追溯。
- **优先级**：P1（TopHap MCP 已有基础，见 docs/tophap-mcp-integration.md）。

### 3. 固定字段 Schema + 抽取置信度——AI Extract 的工程化纪律
- **Dealpath 具体怎么做**：抽取不开放式问答，而是**固定 schema（90+ listing & property 字段）**，每个字段从 OM/flyer 定位抽取，官方口径准确率 95%、<1 分钟（businesswire 2025-10-14）。新 doc 类型（debt OM：acquisition/refinance/construction/bridge）是**按 schema 扩展**，不是换模型。（证据：https://www.businesswire.com/news/home/20251014487511/en/Dealpath-Introduces-AI-Studio-to-Power-the-Next-Generation-of-Data-Driven-Investment）
- **对 DealDesk 的启发**：DealDesk 的 intake 抽取应从"LLM 自由抽取"收敛为**固定字段清单**（地址/售价/NOI/租金表/T12/税费/HOA/贷款余额/利率/DOB violations 等，每类 deal 一个 schema 版本），每个字段带**来源标注（哪份文档第几页）+ 置信度**。低置信字段标黄待人工确认——这正是 450 W 44th 那种 AS-IS + DOB violations deal 最需要的（卖方 flyer 数字不可信，字段级溯源=独立验证的证据链）。docs 下已有 uw-field-lineage.md，可把 lineage 从承销页前移到 intake 抽取层。
- **优先级**：P0（与现有"独立验证先于结构设计"铁律直接对齐）。

### 4. Buy-Box 自动打分排序——Deal Screening & Scoring（Agents 路线图）
- **Dealpath 具体怎么做**：路线图中的 agent 能力——*"Deal Screening & Scoring: Auto-scores deals against firm criteria, flags mismatches, and ranks opportunities"*；背后是每家机构的 buy box（投资标准：区域/价格带/回报门槛）。deal 一进 pipeline 就按 buy box 打分、标出不匹配项、排序。（证据：https://www.dealpath.com/ai/ "What's Coming: Dealpath AI Agents"）
- **对 DealDesk 的启发**：Miao 的 buy box 是已知且硬的——**可用资金很少**（2026-09-28 亲口）、每笔必须标全口径现金需求（首付+交割费+储备金+首年 capex/TI）。DealDesk intake 后应有一道**自动初筛打分**：全口径现金需求 vs 可用资金（红/黄/绿）、DSCR、cap rate vs 目标、DOB violations 扣分项。打分规则写成可配置的 YAML（不是写死代码），Miao 改标准不用改代码。这比"人工看三栏再判断"快一个数量级，且让 pass 掉的 deal 留下**书面 pass 理由**（deal intake SOP 要求）。
- **优先级**：P1。

### 5. DealDesk MCP Server——把 pipeline 暴露给 Miao（学 Dealpath MCP）
- **Dealpath 具体怎么做**：*"Dealpath MCP brings your pipeline, comps, and portfolio directly into apps like Claude and Copilot, so your team can get quick, accurate answers in plain English without leaving the tools they already use."* 本质：**MCP server 暴露结构化 deal 数据**，AI 助手用自然语言查 pipeline/组合，答案锚定实时数据而非通用知识。（证据：https://www.dealpath.com/ai/ FAQ）
- **对 DealDesk 的启发**：这是 N=1 场景下**最贴身**的一条。DealDesk 的"用户"就是 Miao（AI agent）。做一个 DealDesk MCP server（deal 列表/详情/承销结果/comps/状态），Miao 在任何对话里问"450 W 44th 现金需求多少""在 DD 的 deal 有几笔"都能拿到实时数，不用翻 UI。技术路线已有先例（docs/tophap-mcp-integration.md 是反向：DealDesk 调外部 MCP；这里是 DealDesk **被** MCP 调）。只读 scope 起步，写操作（改状态/删 deal）后加。
- **优先级**：P0/P1（直接服务"运营 Miao 的人生"主线；D470 技能盘点可把 DealDesk-MCP 列为第一批双录入技能）。

## 不适合我们的（大机构协作能力，N=1 学了是负担）

1. **多人协作治理全套**：role-based permissions、SSO、audit trail、collaborator 可见范围控制、IC 审批流、white-glove 6-8 周实施、**5 用户起售**。DealDesk 只有一个用户（Miao），权限模型=无，审批流=他自己点头。照搬=给一个人造监狱。
2. **Dealpath Connect 私募 listings 交换网络**：本质是机构间网络效应产品（JLL/CBRE 把 listing 直灌 buy-side pipeline，19k listings/$930B）。N=1 没有 broker 网络可接；Miao 的 deal 来源是姐姐转让、broker 关系、私人渠道，学这个形态没有供给侧。
3. **Portfolio/Asset 管理层**：fund allocation、hold/sell/refi 组合决策、investor reporting、LP 报告。那是管基金的工具；DealDesk 管的是**单笔交易核保**，Miao 的"组合"就几套房，组合视角一条 dashboard 够了，不需要资产管理模块。
4. **Outlook 集成 + AI CRM Summary**：broker 关系维护、interaction 摘要——那是机构销售团队的需求。Miao 的关系维护在 IG/微信私聊里，不在 Outlook。
5. **Debt origination 工作流**（lending 页面：term sheet 自动生成、covenant 监控 DSCR/debt yield/LTV）：Dealpath 有专门的 lender 产品线。DealDesk 是 buy-side 收购核保，不放贷，这条产品线整体不适用（但 debt OM 抽取 schema 的思路见第 3 条可借鉴）。
6. **定价与实施模式本身**：企业定制 ~$12k/年起、实施 6-8 周、实施期就开始计费（被用户骂的点）。DealDesk 是自研 $0 栈，这条是反面教材：**永远不要让工具的上手成本超过它省下的时间**。

## 一句话总结

Dealpath 证明了"结构化 deal 数据库 + AI 挂件（抽取/筛查/comps/文档生成/MCP）"这条路在 CRE 是成立的；DealDesk 作为 N=1 台子，最值得抄的是它的**产品化 AI 动作**（tear sheet、comps attach/pass、固定 schema 抽取、buy-box 打分、MCP 暴露），最不该抄的是它的**机构协作包袱**（权限/审批/实施/网络效应）。
