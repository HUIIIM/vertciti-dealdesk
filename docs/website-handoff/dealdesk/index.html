product · 产品

DealDesk 交易核保台

把一笔房地产交易从看房、核保、上投委会到持有期复盘放在一张台面上：住宅看月供与现金回报，商业看 IRR、DSCR 与 NOI；每个关键数字都写明从哪来、谁核过。缺的数显示“—”，不拿 0 凑。MIT 开源、自托管，数据只留在你自己的服务器上。

features · 能力

能做什么

住宅与商业双轨核保

住宅按月供、现金回报与买家清单打分；商业从租金表、T12 算到 NOI、Cap Rate、DSCR 与 IRR。每次运行有编号，任何人可按编号重算，核对结果是否一字不差。

每个数字一本护照

关键数字记录来源文件、页码、可信度和复核人；开启认证后，录入人不能自己复核（四眼原则）。跨来源对不上的数单列为矛盾，裁决前不当真。

先核哪个

别人只告诉你“有几处待核”；这里把每一处按“它能让主回报指标摆动多少个基点”排序，第一条就是最该先去追的那份文件。

反方备忘录，不经 AI

上投委会前，系统先写“这笔交易最可能怎么失败”：擦边的淘汰条件、押在单一假设上的结论、亏钱的悲观情景、没核完的数。每条由固定规则拼成，可复现，数据不足就不写。

反推最高出价

把所有淘汰条件（DSCR 底线、现金回报、IRR 等）同时代入，反推还能出的最高价，并标出卡住价格的那一条；拖动价格可以即时试算每条底线还剩多少余量。

投委会到持有期复盘

投委会材料一键生成，主席一票否决；买入后录实际 NOI，对照当时的承销逐条归因“错在哪条假设”。角色权限分主席、分析师、查看者，所有改动写入审计时间线。

deploy · 部署

怎么用起来

在线版是创始人自用的生产环境（N=1 实证）。自己部署：Python 3.11 以上，一条 ./run.sh 在本机起服务；生产用 Postgres。界面中英切换，61 个 REST 接口附 OpenAPI 规范。
