> 产品团队（架构师＋设计师）双签字输出。只出设计，不写代码，工程另派。
> 背景：董事长纠正——"图片要录入"指 **DealDesk 从 TopHap/公开网页拉数据时，平台上的房源照片自动拉进来展示**，
> 不是用户上传。2026-10-02 工程按字面误加的"上传截图"按钮已上线，保留不动（那是"用户自有材料"路径）；

## 一、产品逻辑三问（章程第三章）

### 1. 环节：intake（搜集）

照片落在 **intake** 环节，不碰 underwriting 计算。作用只有一个：
让 Miao 在搜集阶段**一眼确认"这是不是我要的那栋楼"**。

真实痛点：地址输错一位、或同街多栋楼混淆，underwrite 的就是错的物业。
450 W 44th 这种 subject-to deal，物业对错 = 钱对错。照片是最便宜的"对版"手段。

### 2. 省步：省 3–5 步，达标

- 不用它：新标签页 → 搜地址 → 点街景/照片 → 滚动确认 → 回来（3–5 步，还切上下文）。
- 用了它：intake 结果自带照片条，0 步，余光一扫即确认。
- 结论：省 ≥3 步，达到立项线。

### 3. 诚实：标得出来才上

- 每张照片必须标：来源站点 ＋ 抓取时间。
- 照片按"卖方口径"处理：`seller_claimed=true`，claim_label="平台照片、仅供外观参考"。
  理由：挂牌照可能是精修/旧照，不代表现状——这是诚实铁律在图片上的延伸。
- 无图时明说无图（见第四章），不放占位假图，不编。

## 二、架构（产品架构师实测结论）

### 2.1 各数据源图片能力 — 实测为准，不编

| 数据源 | 有无图片 | 证据 |
|---|---|---|
| TopHap MCP | **无** | 2026-10-02 实测：`enrich_address("450 W 44th St, New York, NY 10036")` 返回 26 字段；劫持 `_map_detail` 打印 raw record，**81 个 key 全量检查，无 photo/image/picture/thumbnail/media 类字段**。`listing` 字段为 null（未挂牌），`mapUrl` 是网页不是图，`pdfReportUrl` 是 PDF 报告。TopHap 是公共记录数据，不是挂牌平台，天生无房源照。 |
| RentCast | **无** | property-data-schema（代码注释引自 developers.rentcast.io）字段全为文本/数值，无图片字段。账号未激活（Not Subscribed），无法 live 实测，以 schema 为准。 |
| 公开网页 | **弱、有条件** | 机制验证通过：`og:image` 提取正则在 realtor.com 实测命中（HTTP 200）。但 homes.com 直接 403；DDG 搜索本轮对测试地址零返回（时灵时不灵）。结论：**"有就捡"，不能承诺**。 |
| Census | **无** | 地理编码器，只返回州。 |

**一句话架构结论**：四个源里三个天生无图；唯一能出图的只有"公开网页抓到的房源页 og:image"，
且受反爬限制命中率低。任何承诺"每地址必有图"的设计都是撒谎。

### 2.2 架构位置图（文字版）

```
地址输入
 └─ providers.run_chain()                      # 现有链，不动
      ├─ TopHapProvider.enrich()                # 图片：无（实测 81 key）
      ├─ RentcastProvider.enrich()              # 图片：无（schema 无图字段）
      ├─ WebProvider.enrich()
      │    └─ research_pipeline.run_web_collection()
      │         └─ ★ 新增 extract_images(html, source_url)
      │              ├─ 提 <meta property="og:image">（主图，必提）
      │              ├─ 同页再提最多 2 张（去重、防臃肿）
      │              └─ 每个成功 fetch 的页面都提 → 按源去重 → 最多 3 张
      │    └─ research_pipeline.run_url_pipeline()   # 用户粘贴房源链接时
      │         └─ ★ 同上 extract_images（此路径命中率最高：用户给了精确页面）
      └─ CensusProvider                         # 图片：无
 └─ 合并（run_chain 现有 key 合并规则复用）
      └─ ★ 新增字段 property_photos（格式见 2.3）
           优先级：用户粘贴链接的图 ＞ 公开网页 og:image；
           TopHap / RentCast / Census 对此字段无贡献
 └─ 缓存：照片 URL 随字段进 24h 地址缓存（URL 可能过期 → 前端懒加载失败时静默隐藏）
```

### 2.3 字段格式（与现有字段格式对齐）

```json
{
  "key": "property_photos",
  "label": "房源照片",
  "value": [
    {"url": "https://…jpg", "source": "realtor.com 页面",
     "source_url": "https://www.realtor.com/…", "fetched_at": "2026-10-02 21:10",
     "caption": "挂牌主图"}
  ],
  "display": "3 张（realtor.com）",
  "source": "公开网页",
  "source_url": "",
  "fetched_at": "2026-10-02 21:10",
  "confidence": "中",
  "seller_claimed": true,
  "claim_label": "平台照片、仅供外观参考",
  "note": "挂牌平台公开图片，可能为精修/旧照，不代表现状；以实地看房为准",
  "status": "filled"
}
```

### 2.4 明确不做的（架构师裁决）

- **Google Street View / Bing Streetside**：要 API key，有付费墙，违"能不花钱就不花钱"铁律。不做。
- **服务端截图 TopHap 地图页**：需无头浏览器，重、脆弱、Vercel 上跑不动。不做。
- **下载图片存服务器**：Vercel 无状态存不住；且费带宽/CPU。只存 URL，前端直链。
- ** hotlink 几十张**：版权/带宽风险，最多 6 张。

## 三、界面设计（产品设计师）

### 3.1 工作台 intake 结果区（`#intake-results`，sec-intake）

**位置**：字段表格**上方**，disclaimer 下方。理由：照片是"对版"用的，必须先看再看数字。

**有图时**：
- 横向滚动照片条，最多 6 张缩略图，统一高 120px，圆角 8px，间距 8px。
- 每张下方一行 11px 灰色小字：`来源 · 抓取时间`（如 `realtor.com · 10-02 21:10`）。
- 照片条右上角小徽章：`平台照片、仅供外观参考`（琥珀色描边，与现有"待验证"徽章体系一致）。
- 点击任意一张 → **新标签页打开原图 URL**（不做灯箱：省工程量；外链原图最诚实，避免我们裁剪失真背锅）。

**无图时**（一句话，不留空白悬念）：
> 灰色 12px 小字单行：`该地址暂无公开房源照片（TopHap/RentCast 为公共记录不含图片；挂牌网站有反爬限制）`
- 不渲染空相框、不放占位图、不 loading 转圈（搜集已结束，转圈是撒谎）。

### 3.2 商业页（uw-commercial.html）

**位置**：A 栏顶部物业信息区右侧，加"外观"小图（首张，宽 160px，高自适应，圆角）。
点击 → 新标签页开原图。`title` 悬停显示来源与抓取时间。

**无图时**：该区域**整块不渲染**（商业页是测算台，不做解释性空状态；解释只在工作台 intake 出现一次，避免 clutter）。

### 3.3 前端工程要点（给工程，非设计但必须交代）

- `<img loading="lazy" referrerpolicy="no-referrer">`：懒加载＋防盗链（部分图床拦 referer）。
- `onerror` 静默隐藏该张：图片 URL 过期是常态，不弹错、不破图。
- 照片不进"一键填表"（WB.fillForm）：照片不是数字字段，不填表，只展示。
- 缓存二次命中时照片随字段 0.7s 内返回（现有缓存机制复用）。

## 四、验收标准（工程交付时产品团队按此验收）

1. 粘贴一条 realtor.com（或同类可抓）房源链接 → intake 结果出现照片条 ≥1 张，来源标注正确，点击新标签页打开原图。
2. 纯地址搜集 → 有图则显示照片条；无图则显示第四章那句灰色话；**不出现破图、不出现空白相框**。
3. 任一照片下方来源/时间标注缺失 → 不算通过（诚实项一票否决）。
4. 地址缓存命中时二次搜集带图返回，无需重新抓取。
5. 商业页：有图显示首张小图，无图时该区域不渲染、页面不错位。

## 五、与现有功能的分工（一句话备忘）

- "上传截图"按钮（用户自有材料：他手机里的照片/截图）——保留，intake 另一入口。
- 本稿"平台自动拉图"（TopHap/网页链路顺手捡的公开照片）——新增，零操作。
- 两者互补：一个解决"我手里有图"，一个解决"平台上有图"。不合并、不互相替代。
